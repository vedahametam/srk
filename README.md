# sriramakrishna.in — headless frontend

A Next.js 16 (App Router, TypeScript, Tailwind v4) frontend for [sriramakrishna.in](https://www.sriramakrishna.in), with WordPress as a headless CMS behind it. Every existing WordPress URL is served at the same path.

## Quick start

```bash
npm install
cp .env.example .env.local   # leave WORDPRESS_URL empty to use sample content
npm run dev                  # http://localhost:3000
```

Without `WORDPRESS_URL` the site runs on built-in sample content (`src/lib/wp/mock.ts`), so the design can be worked on without a live WordPress.

## How routes are kept intact

Permalink structure: `/%year%/%monthnum%/%day%/%postname%/`. `trailingSlash: true` keeps WordPress's trailing slashes.

| URL | Served by |
| --- | --- |
| `/` | Designed home page (`src/app/page.tsx`) |
| `/2026/09/24/sample-post/` | Post, resolved in `src/app/[...uri]/page.tsx` via `src/lib/routing.ts` |
| `/2026/`, `/2026/09/`, `/2026/09/24/` (+ `/page/N/`) | Date archives |
| `/articles/` (+ `/page/N/`) | Posts page. Set `postsIndexPath` in `src/lib/site.ts` to match *Settings → Reading → Posts page* |
| `/any/nested/page/` | WordPress pages, matched on their full parent path |
| `/category/…/`, `/tag/…/`, `/author/…/` (+ `/page/N/`) | Taxonomy and author archives |
| `/?s=term` | Rewritten to `/search/` |
| `/feed/`, `/…/feed/`, `/sitemap_index.xml`, `/*-sitemap.xml`, `/wp-sitemap*.xml` | Proxied from WordPress with links rewritten |
| `/wp-content/…`, `/wp-includes/…` | Proxied to WordPress (uploads, Elementor assets) |
| `/sitemap.xml`, `/robots.txt` | Generated by Next.js |

Like WordPress, a post URL with the wrong date, or a bare `/slug/`, is sent to the canonical permalink with a permanent redirect (308).

## Elementor

Pages and posts built with Elementor are shown with Elementor's own layout. Their stylesheets are read from the page WordPress renders (`getElementorStyles` in `src/lib/wp/client.ts`), keeping only Elementor's assets and leaving out the theme's. Things to know:

- Elementor Pro theme-builder headers and footers are replaced by this site's header and footer.
- Widgets that need Elementor's JavaScript (sliders, tabs, accordions, popups, motion effects) render as static markup. Check these pages and rebuild the important ones as native Next.js components.
- Classic and Gutenberg content gets the site's reading typography instead (`.wp-prose` in `globals.css`).

## SEO

When Yoast SEO is installed, its `yoast_head_json` titles, descriptions, canonicals and OG images are used. Otherwise they are derived from the entry.

## Images

Hand-picked images for the designed pages live in `src/content/images.ts`. Any slot without a `src` shows an ornamental placeholder saying what belongs there. To fill one, add the file under `public/images/` (or use a `/wp-content/uploads/...` path) and set `src`. Featured images from WordPress are used automatically.

## Going live (suggested setup)

1. Move WordPress to `cms.sriramakrishna.in`, with both *WordPress Address* and *Site Address* set to it, so it can still render Elementor pages.
2. Keep it out of search results with an `X-Robots-Tag: noindex` header on that host. Do **not** tick *Discourage search engines*: Yoast would pass that noindex through the API to this site.
3. Deploy this app (Vercel or any Node host) on `www.sriramakrishna.in` with the env vars from `.env.example`.
4. Add a publish webhook: `POST https://www.sriramakrishna.in/api/revalidate/?secret=…` with body `{"slug":"…","type":"post"}` (no body refreshes everything). Without it, content refreshes every `WORDPRESS_REVALIDATE_SECONDS`.
5. Menus: the public REST API doesn't expose WordPress menus, so navigation is in `src/lib/site.ts`. Keep its links identical to the live site's.

## Project layout

```
src/app/            routes (home, catch-all permalinks, archives, search, feeds proxy, revalidate API)
src/components/     header, footer, ornaments (mandala, lotus, diya), cards, views
src/content/        editorial content for designed pages (teachings, timeline, image slots)
src/lib/wp/         WordPress REST client, sample data, HTML/link helpers
src/lib/routing.ts  permalink parser
```
